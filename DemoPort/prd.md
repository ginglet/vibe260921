## 1. 배경 및 목적

### 1.1 배경
장경수는 바이브코딩(AI와 대화하며 개발하는 방식), Django, SQL을 주력으로 하는 개발자이다. 이력서나 SNS만으로는 실제 작업물과 개발 방식을 충분히 보여 주기 어렵다. 그래서 작업물과 역량을 한곳에서 보여 주고, 문의를 받을 수 있는 개인 프로필 사이트를 만든다.

### 1.2 목적
- 방문자(채용 담당자, 클라이언트, 동료 개발자)가 **1분 안에** 누구이고, 무엇을 잘하고, 어떤 결과물을 만들었는지 파악하게 한다.
- 프로젝트 문의와 협업 제안을 **웹 폼으로 바로** 받을 수 있게 한다.
- 사이트 자체를 Django + SQL 역량과 바이브코딩 작업 방식을 보여 주는 **포트폴리오 사례**로 활용한다.

### 1.3 성공 지표 (출시 후 3개월 기준, 초기 목표안)
| 지표 | 목표 |
|---|---|
| 방문자 → 문의 전환율 | 2% 이상 |
| 첫 화면 로딩 시간 (LCP) | 2.5초 이하 |
| Lighthouse 점수 (성능/접근성/SEO) | 각 90점 이상 |
| 프로젝트 상세 페이지 조회 비율 | 전체 방문의 30% 이상 |

## 3. 범위

### 3.1 포함 (In Scope)
- 공개 페이지: 홈, 소개, 기술 스택, 프로젝트 목록·상세, 연락처
- 문의 폼과 문의 내역의 DB 저장
- Django 관리자(Admin)를 통한 콘텐츠 관리
- 반응형 웹(모바일·태블릿·데스크톱), 기본 SEO

### 3.2 제외 (Out of Scope, v1)
- 회원가입과 로그인 (방문자용)
- 블로그, 댓글 기능
- 결제, 예약 기능
- 다국어 지원 (한국어만 제공, 추후 검토)

## 6. 기술 스택 및 아키텍처

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 / 프레임워크 | Python 3.12+, Django 5.x | 장경수의 주력 스택 |
| 데이터베이스 | 개발: SQLite / 운영: PostgreSQL | Django ORM과 직접 SQL을 함께 사용 |
| 프론트엔드 | Django Template + HTML5 + CSS3 + 최소한의 JavaScript | 별도 SPA는 사용하지 않는다 |
| 스타일 | 순수 CSS 또는 Tailwind (구현 시 확정) | 반응형 필수 |
| 정적/미디어 파일 | WhiteNoise(정적), 이미지 업로드는 Django Media | |
| 배포 | 후보: Render, Railway, PythonAnywhere 등 | 도메인·HTTPS 포함 |
| 개발 방식 | 바이브코딩(AI 코딩 도구 활용) + 사람의 리뷰·테스트 | 6.2 참고 |

### 6.1 데이터 모델 (초안)

| 모델 | 주요 필드 |
|---|---|
| `Profile` | name, headline, bio, photo, email, github_url, extra_links |
| `SkillCategory` | name, order |
| `Skill` | category(FK), name, level, is_core(주력 여부), order |
| `Project` | title, slug, summary, description, role, result, thumbnail, demo_url, repo_url, is_featured, is_published, order, created_at |
| `ProjectImage` | project(FK), image, caption, order |
| `ProjectSkill` | project ↔ skill (M2M) |
| `Experience` | type(경력/학력/활동), title, organization, start_date, end_date, description |
| `ContactMessage` | name, email, subject, message, created_at, is_read, ip_hash |

SQL 역량을 보여 주기 위해 목록 조회(태그별 프로젝트 수, 대표 프로젝트 정렬)에 집계 쿼리와 인덱스를 적용하고, 그 설계 근거를 소개나 프로젝트 문서에 기록한다.

### 6.2 바이브코딩 개발 원칙
- AI에게 작업을 맡기기 전에 요구사항과 수용 기준을 문서(이 PRD)로 먼저 정리한다.
- 기능 단위로 작게 나누어 생성하고, 매번 실행·테스트로 검증한 뒤 커밋한다.
- AI가 만든 코드는 보안(입력 검증, CSRF, SQL 인젝션), 성능(N+1 쿼리)을 사람이 리뷰한다.
- 주요 프롬프트와 의사결정은 기록해 두었다가 "바이브코딩 작업 방식" 콘텐츠로 활용한다.

## 7. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 페이지당 이미지 최적화(WebP, lazy loading), 쿼리 수 최소화(`select_related`/`prefetch_related`) |
| 반응형 | 360px 모바일부터 1440px 데스크톱까지 레이아웃이 깨지지 않을 것 |
| 접근성 | 시맨틱 HTML, 대체 텍스트, 키보드 탐색, 명도 대비 WCAG AA |
| SEO | 페이지별 title/description, Open Graph 태그, sitemap.xml, robots.txt |
| 보안 | HTTPS, CSRF 보호, 관리자 URL 변경, 비밀키와 DB 정보는 환경변수로 관리, 문의 폼 스팸 방지 |
| 개인정보 | 문의로 수집한 이메일과 내용은 응대 목적으로만 사용하고, 폼 하단에 수집 안내를 표시한다 |
| 호환성 | 최신 Chrome, Edge, Safari, Firefox와 모바일 브라우저 |
| 유지보수 | 콘텐츠는 코드 수정 없이 Admin에서 관리, 테스트 코드(핵심 뷰·폼) 작성 |

## 8. 디자인 방향

- **톤**: 깔끔하고 신뢰감 있는 개발자 포트폴리오. 과한 장식보다 가독성과 콘텐츠를 우선한다.
- **키워드**: 미니멀, 코드/터미널 감성의 포인트, 충분한 여백.
- **색상**: 어두운 배경 + 1개의 포인트 컬러(구현 시 확정), 라이트/다크 대응.
- **타이포그래피**: 본문은 한글 가독성이 좋은 산세리프, 코드 표기에는 고정폭 글꼴을 쓴다.
- 디자인 시안은 구현 전에 홈과 프로젝트 상세 2개 화면부터 확정한다.
